- 重新构建 `frontend/dist`。

## 全局玻璃模糊失效根治（HomePage 卡片、主题面板等）

**问题**：顶栏模糊正常，但 HomePage 中心卡片与主题设置面板完全不模糊（模糊度拉满 40px 也无效）。

**根因（两个独立问题叠加）**：
1. **lightningcss 吞掉标准 backdrop-filter**：`index.css` 中 `.glass/.glass-strong/.glass-card` 手写 `backdrop-filter` 在前、`-webkit-backdrop-filter` 在后，rolldown-vite 的 lightningcss 压缩去重时保留最后一条（-webkit- 版），丢弃标准属性。Chrome 从未实现过 `-webkit-backdrop-filter`（Safari 专有），计算样式为 `none`。Tailwind 生成的类因顺序相反不受影响；inline style（LoginPage/Header/toast）不经过压缩也不受影响——这解释了为何只有部分元素失效。
2. **Backdrop Root 隔离**：enter 动画类（`.zen-dropdown-enter`、`.zen-toast-enter` 等）用 `animation-fill-mode: both/forwards` + `will-change: transform, opacity`，动画结束后 transform 动画值永久保持，使元素成为 Backdrop Root。主题面板 portal 容器因此让内层 glass 面板采样不到容器外的背景图。

**修复**（均在 `frontend/src/index.css`）：
- 三个 glass 类改为 `-webkit-backdrop-filter` 在前、标准属性在后（与 Tailwind 生成顺序一致）。
- 所有 enter 动画类（stagger-fade-up、item-enter、modal-content-enter、toast-enter、dropdown-enter、overlay-fade-in、panel-enter-left、dropdown-item、text-reveal、comment-enter、notification-enter）`both` → `backwards` 并删除 `will-change`；`.zen-stagger-fade-up` 的静态 `opacity: 0` 一并删除（backwards 在 delay 期间自动应用 0% 帧）。exit 类保持 forwards 不动。
- 实测确认：Chrome 中元素自身 transform（如 zen-card:hover translateY）不影响自身 backdrop-filter，无需改动。

**验证**：home-blur-40.png（40px 模糊效果明显）、theme-panel-blur.png、card-hover-blur.png、login-regression.png。计算样式 HomePage 卡片 `blur(12px)`（修复前 `none`）。

**注意**：vite build 清空 dist 再次被 safe-delete 拦截，且 preview 运行时会占用 dist 文件导致 PowerShell 删除也失败——需先停 preview 再删 dist 再构建。
