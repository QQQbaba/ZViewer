# 2026-07-24

## 视频加载/seek 性能优化

针对"跳转卡顿 + 跳到未缓存区域等待过长"完成优化,前后端 tsc/eslint 全部通过。

### 前端(MSE 引擎 + seek 编排)

- `seek-service.ts` 重写策略:废除"向前跳未缓冲=干等顺序下载";改为活动缓冲边缘缺口(getGapFromLiveEdge)≤10s 走普通 seek,否则直接 MSE Range seek。新增模块级 pendingSeekTargets(WeakMap<video, number>):锁占用期间到达的 seek 目标不再丢弃,锁内循环接续处理(连续拖拽不丢目标);获取锁时先 delete 防残留。处理跨锁并发:seekTo 返回 busy 时挂 pending 而非走兜底回拉进度。
- `player.ts seekTo`:① state==='seeking' 返回 {busy:true} 而非 fail;② 窗口化清理 clearSourceBufferBefore(仅移除 target 之前的区间,保留之后的缓冲)替代全量 clearSourceBuffer(卡顿主因);③ 清理后即设置 currentTime(UI 即时响应 + 水位基准正确);④ 计算 stopAtTime(首个 target 之后的保留区间起点)传给双轨;⑤ 成功路径漂移检测 |currentTime-target|>1 时不回拉进度。
- `track.ts`:stream/seekStream 支持 stopAtByte(resolveStopAtByte:sidx 精确、无 sidx 线性估算×1.15 膨胀、clamp totalSize);追上保留区间即正常结束,不进水位等待。
- `processor.ts`:新增 freeProgressBytes(缺口字节额度),缺口填补期间豁免前瞻高水位暂停,防止保留区间导致 ahead 虚高、缺口永远填不满。
- `buffer-manager.ts`:新增 clearSourceBufferBefore(队列内逐区间 remove,重置 i=-1 重扫)+ getFirstBufferedStartAfter(纯读)。
- `seek-strategy.ts`:新增 getGapFromLiveEdge + FORWARD_BUFFER_TOLERANCE_SEC=10,已从 services/index.ts 导出。
- `useVideoSource.ts`:handleSeeking 移除 isReloadingRef 早退(改由 executeSeek 记录 pending)。

### 后端(Range 链路延迟)

- `services/webdav.ts`:statWebDAVFileCached(30s TTL + 200 条容量控制),createWebDAVReadStreamWithRange 改用它 —— WebDAV/OpenList 每个 Range 请求少一次 PROPFIND 往返。
- `services/ftp.ts`:statFTPFileCached(同参数);`routes/ftp.ts` proxy 改用它 —— FTP seek 从 2 次登录降为 1 次。
- B站 CDN 代理无需改:undici fetch 默认 keep-alive 连接池。

### 关键设计要点(复用价值)

- 保留区间与缺口填补的配合:stopAtByte(字节停止点)+ freeProgressBytes(水位豁免)缺一不可,否则水位控制会阻止缺口填满导致死等。
- sidx findByteOffsetByTime 返回"包含 t 的 subsegment 起始字节",用作停止点时天然偏安全(多下一个 subsegment)。
- executeSeek 是唯一 seek 入口(房主本地 handleSeeking / 观众 handleState / handleControl 三路),isReloadingRef 每路一把锁,跨锁并发靠 player busy + 共享 pendingSeekTargets 协调。
